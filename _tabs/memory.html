01 The idea

What is memory?

Every photo you view, every tab you open, every unsaved sentence you type exists as electrical charge, magnetic patterns, or trapped electrons — somewhere. “Memory” is the machinery that holds those patterns and hands them to the CPU when asked. The catch: no single technology is fast, big, and cheap at once. So your computer uses half a dozen of them, stacked.

The stack below is real — it is in the machine you are reading this on. The layers near the top are tiny and answer in under a nanosecond; the layers near the bottom hold terabytes and take milliseconds. Data is constantly promoted toward the CPU when it is needed and demoted back down when it is not. Watch it move:

  1. Program the code that wants data
  2. CPU computes on it
  3. Registers the numbers in hand
  4. Cache recently used data
  5. RAM everything running
  6. SSD everything installed
  7. Cloud backup everything, elsewhere

Choose a demo to watch data travel through the hierarchy.

Opening a file pulls it up the stack — disk to RAM to cache to registers — and saving pushes it back down. The further a request has to travel, the longer the CPU waits. Most of the engineering in this exhibit exists to make that trip as short and as rare as possible.

Two very different jobs: working memory vs. storage

In everyday speech, “memory” blurs two ideas that hardware keeps strictly separate. Working memory (registers, cache, RAM) holds what is happening right now, is blisteringly fast, and forgets everything at power-off. Storage (SSDs, hard drives, the cloud) holds what you want to keep, survives power-off, and is thousands to millions of times slower. When your phone says “64 GB,” that is storage. When a game demands “16 GB,” that is RAM. The rest of this page is the story of how the two worlds cooperate.

03 The summit

Registers — the numbers in the CPU’s hand

At the very top of the pyramid sit a few dozen storage slots built directly into each CPU core, each holding one value. Every calculation the machine ever performs happens between registers. They have no addresses and no gigabytes — just names — and they respond within a single clock cycle.

Watch the PC — it counts 0, 1, 2… then jumps back to line 3 each time the loop repeats. Reads flash blue, writes flash teal. Real ISAs have 16–32 general registers (plus vector registers) and the assembly is terser, but this is genuinely how your code runs: values are loaded into registers, combined, and stored back.

Why not just make more registers?

Registers are the fastest storage in the machine because there are so few: every one of them is wired directly into the arithmetic units, and instructions name them in just a few bits. Add thousands and the wiring slows down, the instruction encoding bloats, and you have reinvented a cache — which is exactly what the next chapter is about.

04 The shortcut

CPU cache — a copy of what you’ll want next

RAM is roughly 250 cycles away — an eternity for a core that can finish several instructions per cycle. So CPUs keep small copies of recently used memory in SRAM caches right on the die: a tiny, 4-cycle L1; a bigger, 12-cycle L2; and a large L3 shared by all cores. Temporal locality

If you used a value a moment ago, you will probably use it again soon — loop counters, hot functions, the pixel you keep blending. The tight loop workload wins because its whole working set fits in L1 and stays there.

Spatial locality

If you touched address 1000, you will probably touch 1001 next. Caches exploit this by moving memory in 64-byte lines: one RAM fetch pre-pays for the next fifteen accesses. That is why the sequential sweep still hits ~94% despite never reusing data.

The simulator is a deliberately small cartoon — a handful of cache lines, simplified LRU replacement, no associativity conflicts — but the hit rates and the ~10× performance spread between patterns mirror real hardware. The lesson generalizes: the same computation, ordered differently, can run an order of magnitude faster. Random pointer-chasing is the memory hierarchy’s worst case.

05 The workbench

RAM — where running programs live

Random Access Memory is the computer’s workbench: every open app, every browser tab, every unsaved document occupies part of it while active. “Random access” means any address costs the same to reach — no fast or slow neighborhoods. Open and close the apps below to see a 16 GB module fill and empty.

Notice the allocations are scattered, not tidy blocks — memory is handed out in pages wherever free space exists, and the next chapter explains the illusion that hides this mess from every program.

Why RAM forgets: a bucket with a hole in it

A DRAM bit is one microscopic capacitor: charged = 1, empty = 0. Capacitors leak, so the memory controller must refresh every cell — read it and write it back — dozens of times per second, billions of cells at a time. Cut the power and the refresh stops; within moments every charge drains away and the bits are gone. That is what volatile means, and it is a trade, not a flaw: a 1-transistor-1-capacitor cell is tiny and cheap, which is exactly how you get gigabytes of it. The SRAM in caches uses six transistors per bit — faster, no refresh, but ~100× the silicon per bit. Your machine pairs kilobytes-to-megabytes of SRAM with gigabytes of DDR DRAM because physics offers no single cell that is both.

06 The illusion

Virtual memory — the illusion that never runs out

No program sees real RAM addresses. Each one gets a private virtual address space, and the operating system maps it onto physical memory in 4 KB pages, one page table entry at a time. The payoff: programs can’t trample each other, and when RAM fills up, the OS can quietly park idle pages on disk. Step through what happens when you open one app too many.

The cost of a page fault

Page already in RAM~80 ns
Major fault — fetch from SSD~80 µs — 1000× slower

A page fault is not an error — it is the CPU telling the OS “this page isn’t mapped, go get it.” Touching a page that’s parked on disk (a major fault) suspends the program for the entire disk round trip. A little paging is normal and healthy. But when RAM is so oversubscribed that pages bounce in and out continuously, the machine spends more time moving pages than working — that grinding slowdown is thrashing, and it is exactly what you feel when everything freezes but the disk light blazes. The fix is boring and real: more RAM, or fewer open apps.

07 The vault

SSDs vs hard drives — electrons against machinery

Below RAM sits permanent storage, and here two technologies compete. A hard drive stores bits magnetically on spinning platters and must physically move an arm to reach them. An SSD stores bits as trapped charge in NAND flash and reaches any of them electronically. Race them.

The mechanical numbers compound: to read a scattered 4 KB block, a hard drive pays a seek (the arm swings to the right track, ~4–9 ms) plus rotational latency (waiting for the sector to spin under the head, ~4 ms average at 7200 rpm). An SSD pays neither — which is why the small-file race isn’t close, and why swapping an old laptop’s HDD for an SSD feels like a new computer. NVMe drives push further by speaking PCIe directly to the CPU instead of the older SATA protocol, with deep command queues that keep dozens of requests in flight at once.

08 The cell

Flash memory — bottling electrons

The same NAND flash inside an SSD also powers USB sticks, SD cards, and the storage in every phone. Each cell is a transistor with an insulated charge trap: force electrons in and they stay for years with no power at all — that is why flash, unlike RAM, remembers. Try programming a cell yourself.

One NAND cell

Cell is erased — reads as 1. No electrons in the trap.

A drive’s lifetime: wear leveling

Forcing electrons through the oxide wears it out — each block survives a few thousand program/erase cycles (fewer as cells store more bits: SLC → TLC → QLC trade endurance and speed for capacity). The SSD’s controller runs a flash translation layer that constantly remaps writes so no block wears out before its siblings — the drive that “just works” for a decade is quietly playing musical chairs with your data the whole time. It also can’t overwrite in place: it erases in large blocks and writes in pages, which is why the TRIM command and spare area exist.

10 The physics

Latency vs bandwidth — two kinds of fast

Latency is how long the first byte takes to arrive. Bandwidth is how many bytes arrive per second once flowing. A narrow pipe with a short hose beats a wide highway across the country for a sip of water — and loses badly for a flood. Drag the sliders and switch workloads to feel which one dominates when.

This is why hardware specs quote both numbers, and why neither alone predicts feel. DDR5 RAM moves ~50–100 GB/s with ~80 ns latency; an NVMe SSD can stream 7 GB/s yet still takes ~60 µs to answer. Big sequential jobs — video export, game level loads — ride on bandwidth. Snappy UI, databases, and program launches live and die by latency, because they issue thousands of tiny dependent reads where each one waits for the last. Deep queues and prefetching are the industry’s tricks for hiding latency under bandwidth — and dedicated DMA engines let devices pour data into RAM directly, without making the CPU carry every byte.

11 The FAQ

Common misconceptions

Seven questions that trip up nearly everyone — each with the short honest answer.

Is RAM the same thing as storage?

No — and this is the single most common mix-up. RAM is the volatile workbench for running programs; storage (SSD/HDD) is the permanent shelf for files. “My phone has 128 GB” describes the shelf. A full shelf doesn’t slow the workbench, and a full workbench doesn’t shrink the shelf.

Does more RAM make everything faster?

Only if you were running out. RAM is a capacity, not a speed: 32 GB idle is no faster than 16 GB idle. But the moment your working set exceeds RAM, the OS starts paging to disk at a ~1000× penalty — so going from not enough to enough is transformative, and beyond that the OS just uses the spare as a file cache (nice, not dramatic).

Is cache just a small amount of RAM?

Different technology, different place. Cache is SRAM (six transistors per bit, no refresh) built into the CPU die itself, tens of times faster than the DRAM sticks plugged into the motherboard. It is also invisible: you can’t buy more, and programs can’t address it — the hardware manages it automatically.

SSDs are fast now — why not use one as RAM?

The gap is still enormous: ~80 ns vs ~60,000 ns per random access — roughly a thousand-fold. A CPU waiting on an SSD for every variable would run slower than a 1990s machine. Flash also wears out with writes, and RAM traffic is a firehose of them. SSDs make a fine overflow for RAM (that’s paging) but a hopeless replacement.

Does deleting files free up RAM?

No — deleting files frees storage. RAM is freed by closing programs (or by the OS reclaiming it automatically). The confusion is the workbench/shelf mix-up in action.

Why does restarting my computer fix things?

Because RAM is volatile, a restart is a true blank slate: leaked memory from buggy apps, fragmented allocations, bloated caches, and wedged driver state all vanish, and everything reloads fresh from disk. Rebooting doesn’t “clean” your storage — it empties the workbench.

Is my data “in the cloud” somewhere special?

The cloud is the same hierarchy, continued: your file sits in RAM and on SSDs/HDDs in someone else’s data center, with network latency (tens of milliseconds) stacked on top. It is the slowest, largest, most durable layer — the bottom of the pyramid, reached through a wire.

12 The lineage

Seventy years of remembering

From hand-woven magnetic donuts to terabytes on a fingernail — every layer of today’s hierarchy was once a breakthrough. Scroll the timeline.

  1. 1951

    Magnetic-core memory

    Tiny ferrite rings, threaded by hand onto wire grids, store one bit each by magnetization direction. Reliable, non-volatile — and woven by workers with needles.

    ~1 µs access · dollars per bit
  2. 1956

    The first hard drive

    IBM’s RAMAC 305 stores 5 MB on fifty 24-inch spinning platters. It weighs about a ton and ships by forklift — but data is finally online, not on punched cards.

    5 MB · ~1 ton
  3. 1966–68

    DRAM is invented

    Robert Dennard at IBM realizes one transistor plus one capacitor can hold a bit — leaky, needing refresh, but tiny. The design still powers every RAM stick made today.

    1 transistor + 1 capacitor
  4. 1970

    Intel 1103 ships

    The first commercial DRAM chip — 1024 bits — undercuts core memory on price within two years and kills it. Semiconductor memory takes over the world.

    1 Kb per chip
  5. 1980s

    Flash memory

    Fujio Masuoka at Toshiba invents flash — EEPROM erased in whole blocks in a “flash.” NOR (1984) and NAND (1987) variants set up the next four decades of storage.

    non-volatile, no moving parts
  6. 1989

    Cache moves on-die

    Intel’s 486 integrates 8 KB of L1 SRAM directly on the CPU die. The memory hierarchy as this page describes it — registers, on-chip cache, DRAM — clicks into place.

    8 KB on-die L1
  7. 1991

    The first SSDs

    SanDisk ships a 20 MB flash SSD for laptops at ~$1,000. Absurdly expensive per megabyte — and the beginning of the end for boot-drive spindles.

    20 MB · ~$50/MB
  8. 2000s

    The DDR era

    DDR SDRAM transfers on both clock edges; DDR2 through DDR5 keep doubling transfer rates while multi-channel controllers move to the CPU package itself.

    DDR5: >50 GB/s per module
  9. 2011

    NVMe

    Flash outgrows disk-era SATA plumbing, so the industry writes a new protocol that speaks PCIe directly, with tens of thousands of parallel command queues built for silicon, not spindles.

    μs-class storage latency
  10. 2015

    High Bandwidth Memory

    DRAM dies are stacked vertically and wired to the processor through thousands of connections across a silicon interposer. GPUs and AI accelerators feast on terabytes per second.

    >1 TB/s on modern stacks
  11. 2020

    Unified memory goes mainstream

    Apple’s M1 puts CPU and GPU on one die sharing one pool of on-package DRAM — no copying between “system” and “video” memory. Consoles and AI chips converge on the same idea.

    one pool, every processor
  12. Today

    The hierarchy deepens

    CXL-attached memory, 3D-stacked cache (V-Cache), QLC flash, and HBM4 keep adding rungs. Seventy years in, the ladder from register to archive only grows taller — and the ideas on this page still describe every rung.

    same pyramid, more layers
