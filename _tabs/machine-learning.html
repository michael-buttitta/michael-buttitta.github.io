01 First principles

What is machine learning?

For seventy years, programming has meant one thing: a human works out the rules, writes them down as code, and the computer applies them. Machine learning flips that arrangement on its head. Instead of writing the rules, you show the computer examples with known answers — and it works out the rules itself.

Traditional programming

Rules + Data → Answers

A person writes if sender is unknown and subject contains "FREE!!!" then spam. The computer applies the rule exactly, forever. Great when the rules are knowable and stable.

Machine learning — training

Data + Answers → Learned model
New data + Learned model → Predictions

You show the computer 10,000 emails already labeled spam or not spam. It finds the patterns itself, producing a model — then applies that model to email it has never seen. The second line is called inference, and it is what happens every time a trained model is actually used.

When is each approach the right tool?

Traditional code wins whenever the rules are crisp and you can state them: computing sales tax, sorting a list, validating a date. Machine learning wins when the rules are too fuzzy, too numerous, or too fast-changing for a human to write down: recognizing a face, transcribing speech, or — our running example — deciding whether an email is spam. Nobody can enumerate every spam trick, and spammers invent new ones daily. But given enough labeled examples, a model can keep learning the moving target.

And machine learning is the wrong tool when you have little data, when you need guaranteed, explainable behavior (a bank’s interest calculation should never be “probably right”), or when a dozen lines of ordinary code solve the problem exactly. A surprising amount of real-world engineering wisdom is knowing when not to reach for ML.

02 Orientation

The machine learning landscape

“AI” and “machine learning” get used interchangeably, but they are not the same thing. Each term below is a subset of the one before it. Hover or tap each ring to see where it sits.

Artificial Intelligence

The broad ambition: machines that do things we consider intelligent. Includes ML, but also older rule-based systems, search, and planning — the whole story is on the Understanding AI exhibit.

So: every deep learning system is machine learning, and every machine learning system is AI — but not the other way around. A chess engine that searches moves is AI without ML. A spam filter using decision trees is ML without deep learning. And ChatGPT lives in the innermost ring: a large language model, produced by machine learning, running on the deep learning playbook. This page is about the second ring — the engine room that powers everything inside it.

03 Raw material

Data: the raw material of learning

A model can only be as good as the examples it learns from. Each example is described by features (the measurable inputs) and, for supervised learning, a label (the answer we want predicted). For an email: features might be the number of exclamation marks, whether the sender is known, the word “free” count — and the label is spam / not spam.

Build a dataset — then ruin it

This is a tiny house price dataset: each dot is one house, with one feature (floor area) and one label (sale price). A model — here a simple fitted line — learns from whatever you give it. The dashed curve is the true relationship the model is trying to discover. Click the plot to add your own houses.

Examples 0 Model error vs. truth — Data quality clean

Watch the fitted line: a little noise is survivable, but a few extreme outliers or mislabeled examples can drag the whole model away from the truth. This is the oldest law in the field: garbage in → garbage out. In real projects, most of the work is not modeling — it is collecting, cleaning, and questioning data.

Real datasets also suffer missing values (a sensor failed, a field was left blank) and biased sampling (if every example came from one city, the model learns that city, not the world). A spam filter trained only on English email will happily wave through spam in Spanish — not because the algorithm is bad, but because the data never showed it what Spanish spam looks like.

04 Learning with answers

Supervised learning

The workhorse of the field: learning from examples that come with the correct answer attached. Show the model labeled emails, labeled tumors, labeled house prices — and it learns a function from features to labels. Two flavors: classification predicts a category (spam / not spam); regression predicts a number (this house will sell for $412,000).

Train a spam classifier by hand

Each dot is an email plotted by two features. Pick a label, click to add examples, and a real logistic-regression model retrains live. The shading is the model’s confidence; the bright line is its decision boundary. Notice how few examples it needs before the boundary looks sensible — and how one mislabeled point near the boundary bends it.

Labeled examples 0 Training accuracy —

This widget trains a real (if tiny) model — logistic regression via gradient descent, the same family of algorithm used in production spam filters for years. Real emails have thousands of features rather than two, but the idea is identical: find the boundary that best separates the labeled examples, then use it on new email.

Everyday supervised learning: your bank flagging a fraudulent charge (classification), your weather app predicting tomorrow’s high (regression), a hospital model estimating readmission risk (classification with probabilities). What they share: someone, somewhere, assembled a pile of examples with known outcomes. The “supervision” is that answer key.

05 Learning without answers

Unsupervised learning

Sometimes there is no answer key — just data. Unsupervised learning finds structure on its own: which customers behave alike, which songs belong together, which server logs look anomalous. The algorithm is never told the right answer, because nobody knows it.

Clustering, live

These unlabeled points might be customers plotted by spending and visit frequency. The k-means algorithm below is real: it guesses k group centers, assigns each point to its nearest center, moves each center to the middle of its group, and repeats. Drag the slider and watch the groups reorganize.

Iteration 0 Total distance to centers —

Notice there is no “correct” k — you chose it. The data was actually generated from three groups, so k = 3 fits naturally, but the algorithm will cheerfully carve the same points into 2 or 6. Unsupervised learning discovers a structure, not the structure; a human still has to judge whether it means anything.

The other big unsupervised idea is dimensionality reduction: squeezing data with thousands of features down to a few that preserve most of the interesting variation — like summarizing every movie by two numbers (“how arty, how action-y”) instead of a thousand attributes. It powers visualization, compression, and the recommendation engines that notice you and a stranger have suspiciously similar taste.

06 Learning by trying

Reinforcement learning

The third paradigm has no dataset at all. An agent acts in an environment, receives rewards or penalties, and gradually updates its policy — its habit of what to do in each situation. Action → reward → updated policy, thousands of times over.

An agent learns a maze

This agent knows nothing about the maze — not even that the goal exists. It only feels a small penalty per step, a large penalty in the red trap, and a large reward at the green goal. The colored arrows show its current policy forming as it explores (a real Q-learning implementation, the same algorithm family covered in the AI exhibit).

Episodes 0 Last episode reward —

Early episodes are random flailing; late episodes walk straight to the goal. This trial-and-error family trained game-playing systems like AlphaGo, tunes recommendation feeds, and — as reinforcement learning from human feedback — helped shape how ChatGPT responds. That is the high-level view; we will stay at it and get back to learning from data.

07 The loop

Training: how a model actually improves

“Learning” sounds mysterious, but the mechanism is a plain loop: predict → measure the error → nudge the model to shrink it → repeat. Every mistake feeds a number called the loss, and every iteration adjusts the model’s parameters slightly downhill. Watch it happen, one step at a time.

Watch a model train

The model here is a straight line trying to fit the dots (predicting price from floor area, say). Thin red stems are its current errors. On the right, the loss curve — total error over time — is the heartbeat monitor every ML engineer stares at. Slow it down and step through single iterations to see each nudge.

Iteration 0 Loss —

Two parameters (slope, intercept) make this visible; GPT-class models run the same loop with hundreds of billions of parameters. That scale is why training happens on GPU clusters in the cloud — but nothing about the loop itself changes.

08 Keeping score

Loss: the number that means “how wrong”

Before a model can improve, it needs a single honest number measuring how wrong it currently is. That number is the loss. Lower is better; zero would be perfect. The entire training process exists to push this one number down.

Feel the loss

Drag the line by its handles. Each red stem is one prediction error; the loss adds them all up (here, as squared errors — so big misses hurt disproportionately). Try the presets, then find a better fit by hand than the “good fit” preset.

Loss (mean squared error) — Your best —

Different jobs need different scorekeepers. Predicting a number uses squared or absolute error. Classifying spam uses a loss that punishes confident wrong answers hardest — saying “99% legit” about spam should cost more than saying “55% legit.” Choosing the loss is choosing what the model will care about, which makes it one of the most consequential design decisions in any ML system.

09 Going downhill

Gradient descent: rolling downhill on the loss

Picture every possible setting of the model’s parameters as a point in a landscape, where height is the loss. Somewhere in that terrain is a valley — the settings where the model is least wrong. Gradient descent is beautifully simple: feel which way is downhill, take a small step, repeat.

The descent playground

Click anywhere on the terrain to drop the ball, choose a learning rate — the step size — and run. Can you find the settings that get stuck on the plateau? That overshoot back and forth without ever settling? That land in the shallow dip instead of the deep valley?

Steps taken 0 Final loss — Outcome —

The three classic failure modes are all here: a learning rate too small crawls (or stalls on the plateau, where the ground is nearly flat); too large ricochets past the valley; and descent can settle in a local dip that is not the best solution. One honest caveat: this 1-D cartoon is an educational model. Real deep-learning landscapes have billions of dimensions, and optimizers use momentum, adaptive step sizes, and noisy mini-batches — in those spaces, the picture is stranger and local dips are less of a trap than this hillside suggests.

10 The central tension

Overfitting vs. underfitting

The goal of training is not to ace the examples — it is to generalize to data the model has never seen. A model that is too simple misses the real pattern (underfitting, or high bias). A model complex enough to memorize every wiggle of the training data — noise included — falls apart on new data (overfitting, or high variance). The sweet spot lives between them.

The complexity dial

Solid dots are training data; hollow dots are validation data the model never sees during fitting. Both come from the same dashed true curve plus noise. Drag the complexity dial from 1 to 15 and watch the two error bars — the gap between them is the signature of overfitting.

Underfitting
Training error — Validation error —

The right-hand chart is one of the most important pictures in machine learning: training error falls forever as complexity grows, but validation error is U-shaped. Left of the valley, the model is too rigid (bias); right of it, the model is memorizing noise (variance). For the spam filter, an overfit model has effectively memorized its 10,000 training emails — and flags nothing new, because no new email matches them exactly.

11 Honest measurement

Train, validation, test

If the last chapter taught anything, it is that a model’s score on its own training data means almost nothing. So practitioners split the dataset before touching it: train to learn from, validation to tune decisions like the complexity dial, and a test set opened exactly once, at the end, for the honest final grade.

Split the dataset

Train Validation Test Leaked
Score you would report — Score in the real world —

Toggle the leak. When test examples sneak into training — via duplicated records, or preprocessing computed on the full dataset — the model has already seen its exam questions. The reported score soars; the real-world score does not move. This is data leakage, and it is the most common way ML projects fool their own creators. (The numbers here are illustrative, but the failure is painfully real.)

How big should each slice be? With thousands of examples, something like 70 / 15 / 15 is typical; with millions, the validation and test sets can be proportionally tiny and still reliable. The principle matters more than the ratio: tune on validation, report on test, and never let the test set influence any decision.

12 What counts as good?

Evaluation: accuracy is not enough

Back to the spam filter — now with the question every deployed model faces: which mistakes matter more? Flagging your boss’s email as spam (a false positive) is far worse than letting one junk email through (a false negative). A single “accuracy” number hides that difference entirely.

The threshold dilemma

The model gives every email a spam score from 0 to 100; the two humps are the real spam (rose) and real legit mail (sky). You choose the cutoff. Drag it and watch every metric respond — then try to make precision and recall both happy at once.

Flagged spam Delivered Actually spam Caught 0 Missed 0 Actually legit Lost mail 0 Delivered 0
Accuracy — Precision — of flagged, how much was really spam Recall — of real spam, how much we caught F1 — balance of the two

There is no free lunch: pushing the threshold right protects the inbox (high precision) but lets spam through (low recall); pushing left does the reverse. The right metric depends on the problem. For cancer screening you accept false alarms to miss nothing (recall); for auto-deleting email you must almost never be wrong (precision). For regression tasks the equivalents are averages of miss distance, like mean absolute error. And when one class is rare — 1% fraud — accuracy is nearly meaningless: “never fraud” scores 99%.

14 Setting the record straight

Common misconceptions

Machine learning attracts more mythology than almost any technology. Expand each claim for the honest version.

“More data always means a better model.”

More relevant, clean, representative data usually helps — but more of the wrong data actively hurts. A million biased or mislabeled examples teach the bias more thoroughly. Past a point, the returns also flatten: doubling the data might buy a fraction of a percent. Data quality and coverage beat raw volume.

“AI and machine learning are the same thing.”

ML is one approach within AI — the dominant one today, but not the whole field. Chess engines, route planners, and rule-based expert systems are AI without learning. The nesting diagram in chapter 2 is the map; the AI exhibit covers the full territory.

“Models memorize everything they see.”

A well-trained model does the opposite: it compresses patterns and discards specifics — that is what generalization means. Memorization is the failure mode called overfitting, and practitioners actively fight it. (Models can memorize rare or repeated training snippets, which matters for privacy, but wholesale memorization is neither the goal nor the norm.)

“Machine learning means deep learning.”

Deep neural networks dominate headlines, but vast amounts of production ML is linear models, decision trees, and gradient-boosted ensembles — which often win on tabular business data while being cheaper and easier to explain. Deep learning earns its cost on perception and language, where features are too complex to hand-design.

“95% accuracy means it’s a good model.”

Accuracy is meaningless without context. If 95% of email is legit, “never flag anything” scores 95% while catching zero spam. The evaluation chapter shows why precision, recall, and the costs of each error type tell the real story — and why the number must come from data the model never trained on.

“The model understands the world like we do.”

A model learns statistical regularities in its training data — correlations, not comprehension. It can associate “FREE!!!” with spam without any concept of money or deception, and it can be confidently wrong the moment the world drifts away from its data. Treating pattern-matching as understanding is how ML systems get deployed into situations they silently cannot handle.

The question, answered

So — how does the computer learn to recognize spam?

You can answer it yourself now. Collect thousands of emails people already labeled. Describe each by its features. Split the pile into train, validation, and test before doing anything else. Train a classifier by letting gradient descent walk its parameters downhill on a loss that punishes confident mistakes. Tune the complexity until validation error — not training error — bottoms out. Pick the threshold whose precision-recall trade-off matches what mistakes actually cost. Grade once on the test set, ship, and keep retraining as spammers adapt. No rules were ever written — only patterns, learned from examples, measured honestly.

And the road continues from here. The same loop, scaled to billions of parameters on GPU fleets coordinated in the cloud — with datasets streamed through memory and storage, scheduled by operating systems, and served to you across the internet — is exactly what produced ChatGPT.
